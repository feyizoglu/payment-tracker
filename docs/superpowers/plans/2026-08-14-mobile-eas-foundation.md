# Plan 4a — Mobile EAS foundation (dev build)

> Sub-plan of Plan 4 (EAS/native). Goal: a working **Android development build** (dev client APK) of the current app, so 4b (push), 4d (native Google) and 4e (widget) have something to run on. Native config is written here; the Expo account + `eas build` are run by the user with step-by-step guidance.

**Tech:** Expo SDK 57, EAS Build. Read https://docs.expo.dev/versions/v57.0.0/ conventions (per `mobile/AGENTS.md`).

**Split of work:** config files (`eas.json`, `app.json`, dep install) are written by me; account/login/build commands are run by the user (I cannot log into Expo or run EAS builds).

---

## Context

Mobile line is feature-complete through Plan 3f (Payments, Economy, Reports, Settings tabs all real). Everything native is still missing: no `eas.json`, no `extra.eas.projectId`, no `expo-notifications`, sign-in uses `expo-auth-session` whose native prompt only completes inside a dev build. Nothing can be validated on a device until a dev build exists — that is this sub-plan.

Backend push (`/api/devices`, `src/lib/push.ts`, cron, `devices` table) is already done; 4a just needs the native module present so 4b is pure JS.

Scope: **Android only** (widget target is Android; iOS deferred — no `ios.bundleIdentifier` added). Include the `expo-notifications` native dependency now so the single dev build already carries the push module (avoids a rebuild for 4b).

## Config I write (after U3, because `eas init`/`build:configure` may rewrite `app.json`/scaffold `eas.json`)

### Task 1 — eas.json build profiles
- Create `mobile/eas.json`. If `eas build:configure` already scaffolded one, replace its `build` block with:

```json
{
  "cli": {
    "version": ">= 12.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "android": {
        "buildType": "apk"
      }
    },
    "preview": {
      "distribution": "internal",
      "android": {
        "buildType": "apk"
      }
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}
```

- `development` = dev client APK (Metro-connected, for daily work). `preview` = standalone internal APK (share/test without Metro). Keystore is auto-generated by EAS on first Android build (also yields the SHA-1 that 4d needs for the dedicated Google client).
- Verify: `npx eas build --profile development --platform android --dry-run` or just that JSON parses / `eas build:configure` no longer complains.

### Task 2 — expo-notifications native dependency (present in the first build)
- Install SDK-pinned: from `mobile/`, `npx expo install expo-notifications`.
- Add the plugin to `mobile/app.json` `expo.plugins` (append):

```json
"expo-notifications"
```

- Do NOT write token-registration code here — that is 4b. This task only puts the native module into the build.
- Verify: `npx tsc --noEmit` clean; `npx expo export --platform android` still bundles (the real check per `mobile/AGENTS.md` — tsc alone won't catch Metro/native issues).

### Task 3 — build + smoke test (USER runs the build; we verify together)
- [ ] **Step U4 — build:** from `mobile/`, `eas build --platform android --profile development`. First run: when prompted "Generate a new Android Keystore?", choose **Yes** (EAS stores it). Wait for the build; EAS returns an install URL / QR + `.apk`.
- [ ] **Step U5 — install:** install the APK on an Android device/emulator (scan QR or download).
- [ ] **Step U6 — run:** start Metro with `npx expo start --dev-client` from `mobile/`; open the installed dev client; it should load the app over Metro.
- Smoke check: app launches, tabs (Ödemeler/Ekonomi/Raporlar/Ayarlar) render. Google sign-in **completing** is 4d — not required here; only that the app boots in the dev client.

## Verification (definition of done for 4a)

1. `mobile/app.json` has `expo.extra.eas.projectId`; `mobile/eas.json` exists with the three profiles.
2. `expo-notifications` in `mobile/package.json` deps and in `app.json` plugins.
3. `npx tsc --noEmit` clean AND `npx expo export --platform android` succeeds (bundles) — the mandated mobile check.
4. `eas build --platform android --profile development` produces an installable APK; the dev client opens the app on-device over Metro.
5. Keystore generated on EAS (visible via `eas credentials` → Android) — unblocks 4d SHA-1.

Once 4a is done: 4b (push token → `POST /api/devices`) is pure JS testable on this dev build; then 4c deep links, 4d native Google client, 4e widget.

## Notes / risks

- EAS builds consume build minutes (free tier limited) and take several minutes each — hence minimizing rebuilds (bundling `expo-notifications` now).
- `appVersionSource: remote` lets EAS manage versionCode; no manual bumping.
- No rollback needed — additive config; deleting `eas.json` + reverting `app.json` restores the pre-4a state.
